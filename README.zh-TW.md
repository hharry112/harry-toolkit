# Harry Toolkit

[English](README.md) ｜ 繁體中文

需要 Obsidian 1.7.2 或更新版本。

Obsidian 個人工具箱插件，把幾個自用的小功能收在一起。每個功能都可以在設定裡單獨開關，
關掉的功能不會出現任何指令或畫面。所有資料都存在 vault 內的筆記、Markdown 檔與 JSON 檔，
停用插件後資料仍可正常閱讀。

只有「Threads 數據」會連到外部（Meta 的官方 API，只讀取你自己帳號的數據），
其餘功能完全不連網。

目前收錄三個功能：

| 功能 | 做什麼 |
| --- | --- |
| [捲動](#捲動) | 用快捷鍵捲動內容，游標固定停在畫面上的同一個位置 |
| [文章發佈排程與待辦](#文章發佈排程與待辦) | 發佈月曆、文章排程、待辦事項與到期提醒 |
| [Threads 數據](#threads-數據) | 用官方 API 抓自己帳號的貼文成效，做成排行榜面板 |

---

## 捲動

在長文檔中寫作或校對時，游標停在畫面中間不動，內容一行一行從游標底下流過——
視線不用跟著游標跑，手也不用離開鍵盤。效果類似打字機模式，但由你按鍵控制節奏。

插件提供兩個指令，可在「設定 → 快捷鍵」搜尋「Harry Toolkit」綁定按鍵（例如 `Ctrl+↓` / `Ctrl+↑`）：

| 指令 | 效果 |
| --- | --- |
| 內容上移（游標固定在畫面原位） | 內容往上流過，看到更下面的內容，游標落在新流到眼前的那一行 |
| 內容下移（游標固定在畫面原位） | 內容往下流過，看到更上面的內容 |

- 游標在畫面上的位置（例如畫面正中間）完全不動；游標實際落點會跟著換行，直接就能在新位置編輯
- 快捷鍵可以按住不放連續捲動，也可以單按逐行捲
- 長段落折行也算得正確；連續按時游標經過短行不會左右漂移（保留目標欄位）
- 捲到文件開頭或結尾、游標無法再移動時，游標會自然停在第一行或最後一行
- 在 Source mode 與 Live Preview 都可用；閱讀模式沒有游標，不適用
- 桌面版與手機版皆可使用

### 設定

- **每次捲動行數**：按一次快捷鍵捲動幾行（預設 1，最多 20）
- **平滑捲動**：捲動時帶滑順動畫（預設關閉；需要快速連按時建議保持關閉）

## 文章發佈排程與待辦

給文字創作者用的文章發佈排程管理 + 獨立待辦事項。不串接任何發佈平台。
主畫面是「發佈月曆」（左側 ribbon 📅 圖示或指令開啟），文章排程與待辦都在月曆上操作。

### 發佈月曆

- 以月曆呈現每天「已排程文章」（藍）、「已發佈文章」（綠）、「到期待辦」（紫），逾期項目紅框；一週從星期日開始
- 點日期格子空白處：新增該天到期的待辦（到期日已預填，輸入內容按 Enter 即可）
- 拖曳改期：已排程文章與未完成待辦都可拖到別天，放開即改寫日期；拖曳中懸停在上／下月箭頭約半秒會自動翻頁，可跨月拖曳
- 已發佈文章與已完成待辦不可拖曳
- 標記已發佈：滑鼠移到已排程文章上會出現 ✓，點擊即標為已發佈，**實際發佈日就用它所在那一格的日期**——所以補登以前發的文章，直接把它拖到那天再按 ✓ 就好，不用另外挑日期。預定發佈日會保留，事後看得出來有沒有照原訂日期發
- 取消排程：已排程文章滑過也會出現 ×，點擊即取消排程（狀態改回草稿、清除預定發佈日，平台標記保留），那篇會回到底部的「草稿」區等著重新排
- 標錯了可以退回：已發佈文章滑過會出現 ×，點擊即退回已排程（清除實際發佈日）。原本有預定發佈日就回到那一天，沒有的話就留在原本標記的那天
- 已排定的待辦滑過也會出現 ×，點擊即清除到期日，移回底部「未排定待辦」區（不會刪除待辦本身）
- 待辦左側有小勾勾，可直接在月曆上標記完成
- 待辦有鉛筆按鈕（月曆格子內滑過才出現，底部收合區常駐），點擊可直接原地改內容：Enter 或點別處儲存、Esc 取消，不用開 Todo 檔；到期日與完成狀態不受影響
- 底部依序有五個收合區：「釘選筆記」→「草稿」→「已排定事項」→「未排定待辦」→「檔案瀏覽」；
  上方有「全部展開」「全部收合」兩個小按鈕，一次開關全部五區（想專心看月曆就全部收合）
  - 「釘選筆記」（橘）：列出所有釘選的筆記，點擊以新分頁開啟，按 × 移除釘選
  - 「草稿」（灰）：`publish_status` 是 `draft` 的筆記都列在這裡，最近改過的排前面；**拖到日期格子就完成排程**（狀態自動改成已排程、寫入預定發佈日），拖完它就從草稿區移到那一天。點擊以新分頁開啟筆記
  - 「已排定事項」：所有已排程文章與已排定待辦依日期由近到遠列成總覽（不分月份、不含已發佈文章），每項前面帶日期與星期幾（如 `2026-07-10（五）`），逾期紅框；點擊、小勾勾、× 與拖曳改期等操作與月曆格子上相同
  - 「未排定待辦」：沒有到期日的待辦列在這裡，可直接在區內快速新增，也可拖進日期指定到期日
  - 「檔案瀏覽」：可以一邊看月曆一邊翻資料夾，不用切到檔案總管（詳見下一節）
- 擺放位置隨你高興：把月曆分頁拖到右側邊欄、左側邊欄或主編輯區都可以，**放在哪就一直留在哪**。之後按 ribbon 圖示或「開啟發佈月曆」指令，都是把原本那個月曆顯示出來，不會另外開一個；重開 Obsidian 也會回到原位
- 獨立視窗：在月曆的分頁標籤上按右鍵 →「移至新視窗」（Obsidian 內建功能），可以把月曆整個移到獨立的視窗，放到第二螢幕或擺在旁邊都行；側邊欄太窄時很好用。要搬回去就把獨立視窗裡的分頁標題拖回主視窗。也可以把設定的「月曆開啟位置」直接設成獨立視窗
- 點文章以新分頁開啟筆記；點待辦以新分頁開啟 Todo 檔
- 每日筆記整合：點日期數字以新分頁開啟該天的每日筆記，不存在就先建立（完全跟隨核心外掛「每日筆記」的日期格式、資料夾與範本設定）；已有筆記的日子，日期數字旁有小圓點。核心外掛未啟用時會提示，不會出錯
- 拖放需要滑鼠操作，手機版請改用指令或直接編輯 frontmatter／Todo 檔

### 檔案瀏覽

月曆最底部的收合區，讓你一邊看月曆一邊翻資料夾——側邊欄一次只能顯示一個分頁，
切到檔案總管月曆就被蓋掉了，這一區就是為了免掉那個來回切換。**預設是收起來的**，
月曆展開前的畫面跟沒有這個功能時一模一樣。

- 從 vault 根目錄開始逛，點資料夾進去、點左上角箭頭回上一層；麵包屑（`vault › 文章 › 2026`）每一層都可以點，一下跳回去
- ★ 是常用資料夾：點開列出你設定的路徑，選一個就跳過去；選單最下面可以「將目前資料夾加入常用」，不用另外去設定頁填
- 篩選框只過濾目前這一層，輸入即時生效，換資料夾會自動清掉
- ↑↓ 圖示是排序：可選「檔名（A→Z／Z→A）」「修改時間（新→舊／舊→新）」「建立日期（新→舊／舊→新）」，選了會記起來，重開 Obsidian 仍然照這個排。檔名排序會把 `20260915` 這類檔名照數字大小排；資料夾沒有時間資訊，一律照檔名排（方向跟著設定走）並固定排在檔案前面
- 點檔案在目前分頁開啟，`Ctrl`（Mac 是 `Cmd`）＋點或滑鼠中鍵開新分頁；`.md` 檔不顯示副檔名，圖片、PDF 等其他檔案照常顯示全名
- **筆記可以直接拖到日期格子排程**，效果跟從草稿區拖一樣（狀態改成已排程、寫入預定發佈日）——不限於已標成草稿的筆記，任何 `.md` 都行。非 `.md` 檔案拖不動（沒有 frontmatter 可寫）
- 在檔案或資料夾上按右鍵，有「在新分頁開啟」「在右側開啟」「重新命名」「複製副本」「刪除」，下面接著是其他插件提供的項目（含本插件的「排入發佈行程」「加入釘選」）
  - 重新命名會一併更新指向這個檔的所有連結，跟內建的重新命名一樣
  - 刪除會先跳確認，確認後依你在「設定 → 檔案與連結 → 已刪除檔案」選的方式處理（系統垃圾桶或 vault 的 `.trash`）
  - 複製副本會在同一個資料夾產生「原檔名 1」，適合拿舊稿當模板改寫
- 清單有高度上限並可內部捲動，資料夾裡檔案再多也不會把側邊欄撐長
- 目前停在哪個資料夾與排序方式都會記起來，重開 Obsidian 還在原處；資料夾若被改名或刪除，會安靜退回根目錄

### 文章排程

- 任何筆記都可排入發佈行程，排程資訊存在筆記 frontmatter：`publish_status`（idea / draft / scheduled / published）、`publish_date`（預定發佈日）、`published_date`（實際發佈日）、`platform`（平台標記，選填）
- 指令「將目前筆記排入發佈行程」：跳出日期選擇器，可同時填平台標記；也可在筆記上按右鍵選「排入發佈行程」（檔案總管、分頁標題、編輯器選單、連結右鍵皆可）
- 指令「標記目前筆記為已發佈」：狀態改為已發佈並蓋上今天日期；也可在筆記上按右鍵選「標記為已發佈」。要指定別的發佈日就到月曆上用 ✓（用格子的日期）
- 可在設定中限定只掃描某個資料夾（例如 `文章/`），留空則掃描整個 vault

### 釘選筆記

- 在任何 Markdown 筆記上按右鍵（檔案總管、分頁標題、編輯器選單、連結右鍵皆可）→「加入釘選」；已釘選的筆記同一位置會變成「移除釘選」
- 釘選狀態存在筆記 frontmatter 的 `pinned: true`；移除釘選會直接刪掉該欄位，筆記回到原狀
- 直接手動在 frontmatter 加上 `pinned: true` 效果相同，月曆會自動跟著更新
- 釘選不受「文章掃描資料夾」設定限制，整個 vault 的筆記都可釘選

### 待辦事項

- 待辦與文章無關，儲存在指定的 Markdown 檔（預設 `Todo.md`，可在設定改），格式與 Obsidian 原生 checkbox 相容：`- [ ] 內容 📅 2026-07-10`
- 指令「新增待辦」：不開月曆也能快速加一筆
- 指令「將目前筆記加入待辦」：內容預填目前筆記的 `[[連結]]`，可補充說明與到期日；在 Todo 檔和月曆上都會顯示為連到該筆記的待辦。也可在筆記上按右鍵選「加入待辦」，效果相同
- 直接手動編輯 Todo 檔也可以，月曆會自動跟著更新

### 到期提醒

- 開啟 Obsidian 時與每小時檢查一次，今天到期與逾期的「已排程文章」與「未完成待辦」會跳出通知
- 同一項目同一天只提醒一次，不洗版
- 指令「立即檢查到期提醒」可隨時手動檢查
- 可在設定中關閉提醒

### 設定

- **文章掃描資料夾**：留空 = 整個 vault；填路徑則只掃描該資料夾
- **Todo 檔案位置**：待辦儲存的 Markdown 檔（預設 `Todo.md`），不存在會自動建立
- **月曆開啟位置**：月曆還沒開啟時要開在哪裡——右側邊欄（預設）／左側邊欄／主編輯區分頁／獨立視窗。**已經開著的月曆一律留在原處**，這個設定不會把它搬走
- **到期提醒**：開啟或關閉到期／逾期通知
- **顯示檔案瀏覽**：要不要在月曆底部放「檔案瀏覽」收合區（預設開啟；關掉後整區不出現）
- **常用資料夾**：一行一個資料夾路徑，會出現在檔案瀏覽的 ★ 選單裡
- **檔案瀏覽只顯示 Markdown 檔**：開啟後圖片、PDF 等非筆記檔案不列出（資料夾照常顯示）

## Threads 數據

用 Meta 的官方 Threads API 抓自己帳號的貼文成效，在 Obsidian 裡看排行榜，
並且每天自動記一筆追蹤人數。

**只讀取，不發文。** 這個功能沒有、也不會有發佈貼文的能力。

### 先取得存取權杖

1. 到 [Meta 開發者後台](https://developers.facebook.com/) 建立一個 App，類型選 **Threads API**。
2. 在 App 的「Threads API」設定裡找到 **用戶權杖產生器（User Token Generator）**。
3. 產生權杖時**務必勾選 `threads_basic` 與 `threads_manage_insights`** 兩個權限，
   少勾第二個就只拿得到貼文、拿不到成效數字。
   想連自己的回覆一起抓的話，**再多勾一個 `threads_read_replies`**。
4. 把產生出來的權杖複製起來。

然後在「設定 → Harry Toolkit → Threads 數據」貼上權杖，按 **測試連線**。
成功的話會顯示你的帳號名稱與目前追蹤人數。

> ⚠️ **權杖是明文存放的。**
> 它存在 `<vault>/.obsidian/plugins/harry-toolkit/data.json` 裡，沒有加密
> （Obsidian 插件沒有辦法使用作業系統的加密保管區）。
> 如果你的 vault 有同步或上傳到 Git，這串權杖會跟著出去。
> 它的權限只能唯讀你自己的數據、無法發文，而且 60 天會過期，但仍請自行評估。

權杖效期 60 天。插件會在剩下 10 天內時自動幫你延長一次（Meta 規定權杖要建立滿
24 小時才能延長）。真的過期了就回開發者後台重新產生一組貼上。

### 面板

左側工具列的長條圖圖示，或指令 **開啟 Threads 數據面板**。面板上有：

- **帳號概況**：帳號名、最新追蹤人數，以及跟前一筆紀錄的增減
- **追蹤人數走勢**：最近 90 天的曲線
- **更新最近貼文**：抓設定天數（預設 30 天）內發佈的貼文成效
- **全部重抓**：抓全部貼文的成效
- **排序與搜尋**：可依瀏覽、讚、回覆、轉發、引用、分享或發佈時間排序，也可以搜尋內文
- **含回覆**：預設只看主貼文，勾起來才把回覆一起排進去。
  這個勾選框只管「顯示」，**回覆本身要先抓下來才有東西可看** ——
  見下方「要看自己的回覆」
- 每一列右側顯示六個數字：瀏覽、讚、回覆、轉發、引用、分享，**目前排序依據的那一格會標成強調色**
- 點任何一列會用瀏覽器開啟那則貼文

### 抓取要跑多久

**貼文成效必須一篇一篇單獨問，API 沒有批次版本**，而且每篇之間要停 0.18 秒避免被 Meta 擋。
所以：

| 篇數 | 大約時間 |
| --- | --- |
| 200 篇 | 約 1 分鐘 |
| 500 篇 | 約 2～3 分鐘 |
| 1000 篇 | 約 5 分鐘 |

抓取途中有進度顯示，隨時可以按「停止」——已經抓到的部分會照樣存檔，不會白跑。
日常用「更新最近貼文」就好，「全部重抓」偶爾做一次即可。

**「全部重抓」按下去會先跳確認視窗**，上面會依現有篇數估算大概要跑多久，確認後才開始。

**抓取途中關掉面板分頁不會中斷抓取。** 它跑在插件身上，不是跑在那個分頁上，所以你可以
關掉分頁去做別的事，抓完一樣會跳通知、一樣會存檔。重新打開面板會接上同一份進度，
想停下來就按「停止」。真的要讓它停止的話，關掉分頁是沒有用的。

（會中斷的只有「關掉 Obsidian」或「停用插件」。這時已經跑完的部分還沒存檔，
會整輪白跑——存檔是在整輪結束時一次寫入的。）

### 重抓不會弄壞既有資料

資料檔是**只增不減**的，合併規則是「這輪沒問到成效的貼文，一律沿用原本的數字」。所以：

- 抓到一半按停止 → 沒輪到的貼文不受影響
- 某幾篇讀取失敗 → 那幾篇沿用舊數字
- 重抓再重抓 → 用貼文 id 比對更新，**不會重複堆積**
- 貼文在 Threads 上被刪了 → 記錄仍留在 `posts.json` 裡

### 換了權杖或換帳號

同一個帳號重新產生權杖（或在 Meta 那邊換一個 App 設定檔），直接貼上新權杖、按測試連線即可，
**已經抓下來的資料會繼續沿用**，不用重抓。

資料檔裡記著它屬於哪個帳號。如果新權杖對應的是**另一個帳號**，抓取前會跳出警告，
因為兩個帳號的貼文混在同一個檔案裡，排行榜就沒有意義了。真的要分開管理的話，
到設定改用另一個「資料資料夾」，或先把現有的 `posts.json` 移走。

要整個重來的話，直接把 `posts.json` 刪掉再抓一次就好。
**但不要刪 `account-daily.json`** ——裡面的追蹤人數是補不回來的。

### 要看自己的回覆

回覆**不在**抓貼文的那支 API 裡（`me/threads` 只有主貼文），要另外跟 `me/replies` 要，
所以是獨立的開關。要看回覆的話：

1. 權杖產生時要有 **`threads_read_replies`** 權限（沒有的話回開發者後台重新產生一組）
2. 到「設定 → Threads 數據」開啟 **一併抓取我的回覆**
3. 重新抓一次（「更新最近貼文」或「全部重抓」）
4. 面板上勾 **含回覆**

回覆通常比主貼文多很多，開啟後抓取時間會明顯變長——因為每一則回覆的成效也是要單獨問的。
預設關閉就是這個原因。

**回覆的「回覆數」欄位會顯示「—」。** 這不是抓取失敗：Meta 的 API 對回覆類型的貼文
一律回傳 0，就算那則回覆有幾千個讚也一樣，所以那個數字沒有意義。
瀏覽、讚、轉發、引用對回覆都是正常的。

### 每天自動記錄（很重要）

追蹤人數只拿得到「當下」的數字，**API 不提供查詢歷史，今天沒記就永遠補不回來**。
所以插件會在載入後自動記一筆（一天只記一次，只有兩次 API 呼叫、不到一秒，
失敗也不會影響其他功能）。只要你平常會開 Obsidian，曲線就會自然累積起來。

其他數據的可回補性不一樣：

| 數據 | 能不能補 |
| --- | --- |
| 追蹤人數 | ❌ 補不回來，只能每天記 |
| 帳號每日瀏覽數 | ✅ 可回補到 2024-04-13（指令：**回補每日瀏覽數**） |
| 帳號每日讚、回覆、轉發、引用 | 從開始使用那天起累積 |
| 單篇貼文成效 | ✅ 隨時重抓都是最新的 |

Meta 註明 2024-06-01 之前的數字不保證正確。

### 資料檔

抓回來的東西存成兩個 JSON 檔，放在設定指定的資料夾（預設 `Threads 數據`）：

- `posts.json`：貼文內容與最新成效
- `account-daily.json`：每天一筆的帳號數據（追蹤人數、瀏覽、讚、回覆、轉發、引用）

**檔案放在 vault 裡而不是插件資料夾**，所以移除插件後資料仍然留著，也會跟著你的備份走。
兩個檔都是普通 JSON，可以自己打開看或餵給別的工具。

### 這個功能拿不到什麼

- **單篇貼文帶來多少新追蹤**：官方 API 沒有這個指標。Threads 網頁版看得到，
  但那需要用自動化瀏覽器去抓畫面，Obsidian 插件做不到，也不打算做。
- **別人的帳號數據**：API 只開放自己的帳號。
- **受眾輪廓與連結點擊**：API 有提供，但這個插件不做（2026-09-16 移除）。
  受眾輪廓要滿 100 個追蹤者才有；連結點擊是依網址彙總的帳號層級數字，
  看不出是哪一篇貼文帶來的。

### 設定

- **存取權杖**：見上方說明
- **測試連線**：確認權杖可用，並記下帳號 id
- **資料資料夾**：JSON 檔放哪裡（留空 = vault 根目錄）
- **「更新最近貼文」的天數**：日常更新處理幾天內的貼文（預設 30 天）
- **一併抓取我的回覆**：預設關閉。開啟前先確認權杖有 `threads_read_replies` 權限
- **每天自動記錄帳號數據**：預設開啟，建議不要關
- **面板開啟位置**：面板還沒開啟時要開在哪裡。**已經開著的面板一律留在原處**

## 功能開關

「設定 → Harry Toolkit」裡每個功能一個區塊，區塊第一項是「啟用此功能」。

關掉某個功能後，它的指令、畫面與提醒都會消失，其他功能不受影響。
**開關切換後要重新載入插件才會生效**：到「設定 → 社群插件」把 Harry Toolkit 關掉再開啟，
或按 `Ctrl+R` 重新載入 Obsidian。

## 安裝

### 從社群插件安裝

「設定 → 社群插件 → 瀏覽」搜尋 **Harry Toolkit**，按安裝再按啟用。

### 手動安裝

到 [Releases](https://github.com/hharry112/harry-toolkit/releases) 下載最新版的
`main.js`、`manifest.json`、`styles.css` 三個檔案，放進
`<你的 vault>/.obsidian/plugins/harry-toolkit/`（資料夾不存在就自己建一個），
回到 Obsidian 按 `Ctrl+R`（Mac 是 `Cmd+R`）重新載入，再到「設定 → 社群插件」啟用。

裝好之後，到「設定 → 快捷鍵」搜尋「Harry Toolkit」，為兩個捲動指令綁上喜歡的按鍵。

## 開發

```bash
npm install
npm run dev     # 監看檔案變動自動重建
npm run build   # 正式建置，產出 main.js
```

型別檢查：`npx tsc --noEmit`。

### 程式結構

```
src/
├─ main.ts          進入點：讀設定 → 跑功能清單 → 掛設定頁
├─ core/            Feature 介面、設定疊加、共用設定頁
└─ features/
   ├─ index.ts      功能註冊清單 —— 新增功能只要在這裡加一行
   ├─ scroll/       捲動
   ├─ scheduler/    月曆、文章排程、待辦、提醒、檔案瀏覽
   └─ threads/      API、資料存取、抓取流程、數據面板
```

功能模組不會 import 插件本體，需要的東西一律透過 `FeatureContext` 取得，
所以每個功能都可以獨立增刪，不會牽動其他功能。
